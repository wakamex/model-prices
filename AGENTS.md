# Audience

- model-prices is for general users, so coverage should match what people use, not what the maintainer's own logs contain. Track every lab that sells its own models through an API or a subscription, and do not defer a provider because local usage data shows no calls to it. A subscription is covered by its plan prices in `data/plans.toml`, for every plan the lab sells to individuals and teams, and by an estimate in `data/estimates.toml` for a model sold only in a subscription. Local usage is evidence of a gap, never evidence that a provider is unneeded.

# Price sources

Every price model-prices charges comes from one of the sources below. The daily job and its checks keep each current: a failed check reaches an agent within minutes, and the agent writes the fix. Code writes a price where a page lists it as data; an agent writes a price that needs reading, and dates it by when the provider began charging it, which a parser cannot know. Either way, a price is only as current as the check that reads it.

- models.dev is the base. The daily job reads its git history, which dates each price by the commit that recorded it; a change models.dev records ahead of its date, such as Gemini 4 Argon's on 2026-12-01, enters the history on that date.
- A parsed table, `data/observed.json`, holds a model's prices when models.dev lacks the model and an official page lists it as a row naming the model and its prices, with nothing inferred about which models a statement covers, as Cursor's rate table does. The daily job records a new entry whenever a row changes, dated by the first run that saw it, and earlier periods are backfilled through `research/price_dates.py gaps`. Check every format a page offers before calling it unparseable: Cursor's Markdown copies omit the rate tables that its HTML pages contain.
- Everything else is a dated entry an agent writes from the provider's own docs, changelog, or archived pages, citing the source:
  - a correction, when models.dev records a price late, wrongly, or after the provider retired it, lacks one price of a model it lists, or lacks a model that no page lists as a row. The agent writes it in `data/corrections.toml`; `data/research_corrections.toml` holds corrections that research agents date from quoted sources, and where both cover a time, `corrections.toml` wins. A correction states the model's whole rates for its period, tool fees included. An open-ended correction names in `replaces` the models.dev values it was written against, including every price it restates, and stops as soon as models.dev records a different value for any of them; if the correction is still needed then, the check fails and the agent writes a new one.
  - a rule file, such as `data/batch.toml`, `data/cache_writes.toml`, `data/schedules.toml`, or `data/tools.toml`, for a fee, multiple, factor, or schedule that applies across models and that no page lists per model. Each entry covers its provider's models, or those an explicit pattern or list names, and gives its source and the date it began. A rule that prices only a kind of token that did not exist before it, such as `cache_writes.toml`'s longer-lived writes, needs no start date until its multiple changes. A rule file never overrides a price models.dev records, and `data/tools.toml` only adds a tool fee a model's rates lack, except a regional factor, a time-of-day schedule, or a longer-lived cache write's multiple, where the rule applies and the check compares it with models.dev's.

Each price is checked daily against the provider's official page where one exists. A parser reads one page format without heuristics beyond its layout, so a changed page fails instead of producing a guessed price. Logic that works out which models a rule covers by joining several pages belongs in the check, which fails when the pages and the rule disagree. A disagreement between sources, or evidence that points both ways, fails the check and holds that provider's update for review rather than choosing an answer; a difference a correction accounts for is reported as corrected and does not fail. The check lists every correction in effect for a model no page compared that day as unchecked, so a corrected price no check reads is visible; rule entries and parsed-table prices are not yet listed this way. A price no check could ever read, such as Mistral's batch discount, whose qualifying models its page shows only in a browser, is left out, so `rates(model, mode="batch")` returns no price for those models, and the README says so. A case model-prices cannot price yet, such as a model with both long-context tiers and prices by modality, is recorded without the unpriced part and reported by the check, without stopping other providers' updates.

At a given time, a model's rates are those of the correction in effect, or else models.dev's history, or else, before models.dev's first entry for the model, the parsed table; the choice is per model, so once models.dev lists a model, prices only the parsed table gave it, such as a mode, need a correction. The request then adjusts the rates: its mode selects a service tier, which models.dev records, or the batch discount from `data/batch.toml`, which prices the `batch` mode whatever models.dev records; its time applies a schedule from `data/schedules.toml`; its region applies a regional factor, from a rule file where one covers the model and otherwise from models.dev; and these factors multiply. Tool fees, once priced, are not scaled by any of them. A longer-lived cache write costs `data/cache_writes.toml`'s multiple of the input price after those adjustments, so a batch entry's `cache_write_multiple` prices only ordinary cache writes.

A price's start date says how it is known: `models.dev commit`, which can lag the provider's change by days; `documented`, a date from an entry's source, including an archived page, dated by its snapshot; `first observed`, the first run that read the price on the provider's page; or `scheduled`, a change announced ahead that models.dev recorded. When sources only bracket a change, the earlier documented price applies until the first observation of the new one. A model with no per-token price, such as one sold only in a subscription, gets no invented price: `data/estimates.toml` names a stand-in model, which callers ask for explicitly.

These cases show the routing:

- Perplexity's Agent API search fee replaced the Sonar fee models.dev still lists, so `sonar`'s correction gives it. Its fast search fee, which models.dev never listed, is a rule in `data/tools.toml`.
- OpenAI's preview search fee is $25 on non-reasoning models and $10 on reasoning models. models.dev lacks it and OpenAI's tools table states it per model family, so it is two rules in `data/tools.toml` naming the models by pattern, dated by OpenAI's changelog, and the check compares their prices with the table.
- Gemini 2.5's search fee is billed per grounded prompt, which models.dev lists under a name meaning per search query, so a correction gives the fee under the per-prompt name, and the check reads the unit from each model's grounding row.
- Tencent's and Volcengine's own models that models.dev lacks are listed on pages that name models for display and price them in yuan, so each is a correction under the API id the provider's model list gives, converted at models.dev's rate for that provider, with an empty `replaces` so it stops once models.dev lists the model.
- OpenAI's 10% regional uplift applies to the models a join of its pricing page, data residency table, model pages, and changelog selects, so it is a rule listing those models and their regions, dated by OpenAI's sources, and the check performs the join and fails when it disagrees with the rule. It is currently read into `data/observed_regions.json` by the daily job instead; an agent converts it to a rule when that reader next fails or changes, and adds no rule beside it before then.
